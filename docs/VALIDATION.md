## 大型主库的检查方式

安全主库通过了整本ArtifactTool导入。软工与AI主库在整本SDK导入时触及WASM内存上限，因此将101页按34/34/33页分卷导入。每张幻灯片XML及保留资源与原整本字节一致，全部页面覆盖一次；整本文件另外完成了结构、布局和逐页渲染检查。分卷通过不表述为整本SDK导入成功。

图形路径密集导致解压后的PPT包较大。本批在保留原检查函数的基础上，对已固定SHA的生成文件使用明确的体积阈值：总包512MiB；安全/软工单个XML部分32MiB，AI为64MiB。结构、关系、标题和布局检查未被删除。这属于资源阈值调整，不能表述为未经调整的默认阈值全部通过。

仓库版本仅清理备注中的机器路径。[packaging.json](../validation/packaging.json)逐文件记录这一操作，并证明非备注部分的视觉载荷没有改变。源文件的视觉检查结论因此可对应到仓库版，但原生PowerPoint抽查仍保留为待完成。

## 图形内容的边界

- 字体、线型、阴影、纹理和微小几何可能存在近似，具体说明以各图元数据为准。
- 矢量标注可能已转曲；原生对象不等于全部文字都能直接编辑。
- 从发表图片恢复的统计轮廓不等于原始实验数据。
- 原论文自身的特殊拼写、词元或版面瑕疵，在不更改含义的前提下按源保留，并在检查中记录。
- 密集或纵向图在主库整页中较小，宜使用独立PPTX/SVG放大编辑。

## 本地核对

```bash
python3 tools/check_library.py
```

该命令检查文件数量、清单对应关系、论文与图号重复、PPTX页数、SVG外部依赖、文件校验值、相对链接，以及打包前后的视觉载荷一致性。它不替代人工语义核对或PowerPoint实机检查。
