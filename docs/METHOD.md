# 制作方法

[返回 README](../README.md)

## 选图依据

先定位官方获奖名单，再核对论文文件。范围是2024–2026年已经公布的论文奖，优先安全四大，其次软件工程和AI，三个方向同时整理。每个方向以100张为本批上限，候选不足时按实际值得保留的数量结束。

选择关注图形的表达价值：是否把复杂关系讲清楚，是否有可迁移的分层、分组、局部放大或图例设计，以及是否适合成为科研汇报素材。获奖身份提供明确的来源范围，图是否入选仍需要单独判断。

同一篇论文可以有多张表达用途不同的图。相同图、局部裁剪变体以及缺乏新借鉴价值的重复构图不重复收录。被排除的候选在制作过程里保留原因；本仓库的论文清单记录实际采用的论文。

## 来源如何固定

每张图保留以下对应关系：

| 项目 | 用途 |
| --- | --- |
| 会议、年份、准确奖项名、官方奖项URL | 核对论文奖资格，避免把Artifact等其他奖混入 |
| 论文URL和PDF SHA-256 | 确定使用的是哪个论文版本 |
| 图号、PDF页码、裁剪框 | 定位原图，避免抓错图或剪掉关键内容 |
| 稳定素材ID、论文ID、题名别名 | 对照主PPT与单图，防止版本改名造成重复 |
| 原图参考和复刻预览 | 提供逐项视觉检查依据 |

有些正式出版版本与作者版本的题名或作者列表不同。制作时通过官方论文页、作者信息和内容确认身份，记录差异；不会把两个版本说成字节完全相同。可查阅 [papers.json](../catalog/papers.json) 中的别名及 [provenance.json](../catalog/provenance.json) 中的图源指纹。

## 三种重建路径

### PDF中已有可用矢量

使用PyMuPDF提取指定页与裁剪范围的SVG，读取路径、字形、线宽、颜色、透明度和裁剪关系。通过JavaScript的ArtifactTool运行时创建PowerPoint形状，再按DrawingML结构补回曲线、填充规则、线端和虚线等属性。

文字有时保留为原生文本框，有时作为字形轮廓保留。后一种能保留字体外形并编辑颜色和位置，但不能像文本框一样直接改字。为了将一行标注作为可操作的整体，会合并相邻且绘制属性一致的字形。

### 核心结构只有位图

先拆出容器、节点、箭头、表格、标注、图例与独立科学示例，再用原生形状和文字逐块重绘。

框架、代码示例、表格和流程关系尽量转成原生对象；照片、遥感图、地图数据图层和分子示例可以保留为独立图像。每张图记录保留了哪些图像，避免把整张截图作为“可编辑复刻”。

统计图只能从发表图恢复可见轮廓时，会明确说明这是可见二维几何。接触的散点可能共享一个轮廓，曲面可能以投影色区表达。这不等于恢复了原始观测值、三维数据或模型输出。

### 作者绘图源文件可取得

核对它是否属于同一篇论文、同一张图，再利用作者的矢量图或数据恢复结构。辅助源的版本和校验值单独记录，正式获奖论文的来源仍保持明确。

例如AI-086使用同作者预印本源码中的矢量构图恢复结构，并按正式论文图补回面板标签。高分辨率科学图层与原始矢量字体会与正式PDF中的低分辨率整图位图存在采样差异；这些差异在元数据中说明。

## 制作中实际遇到的问题

| 问题 | 处理方式 |
| --- | --- |
| 箭头相交处出现白洞 | 区分nonzero和evenodd填充规则，按真实裁剪区域处理 |
| 透明占位字形把后面的可见字母一并隐藏 | 字形合并必须同时比较透明度、填充和描边属性 |
| 原生圆弧转换后多出扫线 | 对照另一PDF渲染器的矢量输出，再检查实际曲线 |
| 渐变框出现白边或亮带 | 保留渐变停止点，用同一源边框几何限定填充范围 |
| 公式上下标、箭头或文字丢失 | 返回原图逐项核对，恢复字形或单独重绘 |
| 整图缩入主库后字号、线宽或阴影不协调 | 合并时同步处理这些绝对尺寸，重新渲染整页 |
| 栅格图转写后出现文字重影或细碎接缝 | 分离标注与图形层，并对照原图逐处修正 |

像素差和对象统计用于定位问题。它们不能单独证明复刻忠实：错误箭头、一个漏字或小面积数值错误，也可能只产生很小的总体像素差。

## PPT、SVG与主库

独立图按原图比例建立画布。使用LibreOffice渲染PPT，再由Poppler的`pdftocairo`导出SVG；对照原图与实际渲染，修改后重新检查。

主库采用统一的16:9页面。每页放置素材编号、类型、会议年份、图号、论文题名、借鉴点及来源链接，按六类建立PowerPoint原生分节。合并还需处理对象编号和资源关系，避免图片引用、连接器或形状ID冲突。

仓库打包只改写备注中的本机路径，不改变幻灯片、媒体、主题和几何XML。每份PPT均记录原文件哈希、仓库文件哈希及不含备注的视觉载荷哈希，便于区分“文件字节变化”和“图形变化”。

## 工具与复现边界

本仓库包含成品、结构化来源记录，以及关键的PDF/SVG到PPT转换工具。日常查阅与目录检查只需要文件本身和Python标准库。

运行转换工具需要原论文PDF、Python依赖及本地可用的`@oai/artifact-tool` JavaScript运行时。该运行时及字体、LibreOffice、Poppler不随仓库分发。人工重绘、版本判断和视觉取舍需要根据具体图完成，不能仅凭一个通用脚本自动重建全部300张图。

详见[重建工具说明](../tools/reconstruction/README.md)与[验证说明](VALIDATION.md)。
